# Contributing to TIRD

**Project:** EAV-TIRD-001
**Organization:** Earth Angel Ventures
**Lead:** Angelica Pangan
**Contact:** earthangelventuresph@gmail.com

Thank you for wanting to contribute. This project is open for examination, challenge, and replication — not for silent edits.

## Core Rule

**v1.0 is frozen.**

Do not edit v1.0 directly. If you find an error or want to propose a change, open a 【entity-GitHub¦canonical_name=GitHub】 Issue first. Approved changes go into v1.1, v1.2, etc., with a CHANGELOG entry.

## How To Contribute

### 1. Report a Correction
Found a wrong equation, typo, wrong citation, or wrong figure label?
- Open Issue > Label: `correction`
- Include: File name, line / page, what is wrong, what it should be, source if applicable
- Example: "In README.md, P6 equation missing eta_I term"

### 2. Ask a Question / Challenge the Theory
- Open Issue > Label: `question`
- Be specific. "What is G in P2?" is good. "This is fake" is not a contribution.
- Critique is welcome. Harassment is not.

### 3. Propose a Protocol Improvement
- Open Issue > Label: `protocol`
- Include: Which protocol (E1-E9), what you want to change, why it improves falsifiability, and what the new falsification threshold would be.
- Do NOT propose removing a falsification threshold. Propose making it stronger.

### 4. Propose a Replication
- Open Issue > Label: `replication`
- Include: Lab / institution, which protocol, resources, timeline, ethics status.
- No replication starts until preregistration is agreed.

### 5. Propose Collaboration / Funding
- Email: earthangelventuresph@gmail.com
- Subject: `[COLLABORATION]` or `[FUNDING] EAV-TIRD-001`
- Also open a GitHub Issue for public record.

## What We Do NOT Accept

- Edits that present TIRD as proven when it is not.
- Edits that remove falsification thresholds.
- Edits that add claims of inter-layer travel, portals, or powers.
- Edits that add a product, course, or paid service.
- Edits that add an author who did not contribute.
- Edits that add personal data about participants.
- Pull Requests that change v1.0 files without an approved Issue first.

## Pull Request Process

1. Open an Issue first and wait for approval.
2. Fork the repo, create a branch: `fix/short-description` or `proposal/short-description`
3. Make your change in the branch only.
4. Open a Pull Request linking to the Issue.
5. Wait for review by Angelica Pangan. Only she can merge to main.

## Authorship

Contributions do not automatically equal authorship.

Authorship requires substantial intellectual contribution to theory, protocol design, data collection, or analysis, plus agreement to be responsible for the work.

All contributors will be acknowledged in CHANGELOG.md. Authors will be listed with CRediT roles.
